# Syllable

Syllable 是一个面向 Spotify 的多语言桌面歌词客户端。Windows 上打开 Spotify 桌面端并播放歌曲即可自动同步，不需要先申请开发者账号；也可以选择连接 Spotify Web API。

当前源码为 0.4.23 开发候选版，尚未完整验收。请勿把旧安装包视为最新源码的验证结果。
歌词跨源完整性、自定义转场下的实际听觉同步仍在验证中；以下功能清单不代表所有歌曲均已同步准确。
续作状态见 [CONTINUATION.md](CONTINUATION.md)，待办见 [TODO.md](TODO.md)。本机测试截图和账号缓存不随仓库发布。

## 已实现

- Windows Spotify 媒体会话即开即用：歌曲、封面、播放状态、毫秒进度、暂停、播放、切歌和跳转
- 上一首/下一首使用 Spotify 会话定向控制并带三层防重复锁，避免一次点击连续跳过多首
- 原生媒体桥接运行在独立 Worker；服务异常不会阻塞 Electron 主线程或造成窗口“未响应”
- Spotify 风格黑灰绿客户端界面，使用 Windows 原生字体栈并避免缩放/模糊过渡造成的文字栅格化
- 日文轨道使用系统 Yu Gothic 的 Regular / Medium / Bold 真实字重，并关闭比例假名以保持 CJK 等宽；中文使用 Noto Sans SC / 微软雅黑，英文与界面使用 Segoe UI，均禁用合成字重
- 独立透明置顶歌词窗，可拖动歌词或顶部手柄、从四边原生缩放并自动保存尺寸与位置
- 透明空白像素自动把点击交给下方窗口；控制条仅在鼠标移入歌词窗口时出现，按钮、歌词和原生缩放边缘仍可交互
- 悬浮窗支持背景开关、背景与文字透明度、模糊、圆角、颜色、字重、行距、阴影/描边、位置锁定、鼠标穿透、左右/居中、三档尺寸预设和顶部/居中/底部快速定位
- LRCLIB、网易云和酷狗三源并行查询；除匹配分、版本时长和首尾覆盖外，还会用跨源文本锚点识别中段缺块、错误同歌手歌曲和粗粒度合并行；精确专辑匹配不会再被“把同一句拆成更多行”的搜索结果挤掉
- 日文/英文原文采用身份可靠且更完整的时间轴；中文翻译在覆盖率接近时优先网易云，缺行才由可信同版本来源补齐并重映射到主原文锚点；同一原文区间内延迟到达的多段译文会按顺序保留，不再互相覆盖
- 多级清洗与宽松搜索、服务重试、真实时间标签校验及多候选歌词降级，临时 503 不会再缓存成永久无歌词
- 常规查询缺失、置信不足或命中版本与 Spotify 时长相差超过正常舍入时，才启用网易云艺人页兜底；片假名艺人名会本地折叠成罗马字，并以精确录音时长作为保守指纹，解决 Spotify 英文标题与日文原名毫无共同字符的歌曲
- 同名翻唱不能再仅凭相同曲名、专辑名和接近时长伪造艺人身份；同质量的重复发行只在最后一步用 Spotify 时长决胜，例如 `Suzume` 会选 238560 ms 原声带并保留网易云中文轨，而不是俄语翻唱或 236390 ms 单曲版
- 同时显示原文、中文、英文、罗马音或导入的任意自定义语言轨道
- Kuromoji 分词与 Kuroshiro 日文读音生成；有人工时间轴罗马音时优先使用人工版本
- 人工罗马音漏行或仍含汉字、假名时自动按原时间轴整轨补全，并过滤开头的制作人员信息
- 普通 LRC、重复时间戳、`[offset]` 和增强 LRC 词级时间标签
- 自动拆分同时间戳、轻微错位时间戳及行内分隔的日中双语或日中罗马音三语歌词源
- 歌词搜索、候选分数、逐行改词、取当前时间、整轨 ±100ms、导出和逐曲本地缓存
- 资料库、歌词源、偏好设置、帮助与实时连接诊断页面
- 主窗口关闭后最小化到任务栏，悬浮歌词不中断；单击托盘、再次启动、悬浮控制栏的客户端按钮或 `Ctrl + Alt + S` 都可立即找回
- 播放时钟与视觉动画分离；系统采样之间使用本地时钟投影，暂停时停止无意义刷新；同步校准按歌曲独立保存，不会污染下一首
- 客户端歌词可用鼠标滚轮、触控板或键盘上下浏览；浏览时暂停自动跟随，“回到当前歌词”可立即恢复同步定位
- 封面不向悬浮窗重复复制；跨窗口只同步变化的单曲而非整座资料库，歌词抓取去重、网络缓存有界，Kuromoji 在一次性 Worker 完成后立即释放
- 主界面、透明歌词和控制条复用硬件加速渲染进程，并保持独立原生窗口命中；实机物理点击压力测试通过，同时减少一个 Chromium 进程
- 原文始终保留为同步锚点，中文、日文和拉丁文字分别识别，避免把翻译误当主歌词或把中文送去罗马音化
- Spotify 报告的 position 始终是唯一传输时钟；自定义 Mix 的 cue 只用于诊断，不再加到歌词时间，只有通过校验的速度曲线才做分段积分
- 自定义 Mix 的播放端点与独立已知的原始录音时长分开保存；不会再用淡出起点/时长推断原曲终点或截断歌词时钟
- Spotify 切歌时先确认标题、正时长和转场信息属于同一媒体项，再发起歌词匹配；不会把上一首的正时长配给下一首歌名
- 新歌曲名和正时长发布后，歌词查询只等待 320 ms 事件合并，不再被 Spotify 私有转场读取的约 1.8 秒超时阻塞；后续若发现不同源时长会取消旧渲染结果并按新缓存键重取
- 一轮多源生成共享 5.5 秒上限，超时会中止正在进行的请求及退避等待；已完成的歌词会立即显示，但只要有歌词源瞬时失败就不写入稳定缓存，并在 12 秒后有界重试一次
- 同一歌词源的一路空响应不再掩盖其他查询的 429/503/超时，避免把缺中文、缺罗马音或低位候选固化为“成功”
- LRCLIB 精确元数据时间轴若与两个相互吻合的完整来源整体错开至少 2.5 秒，会被可靠文本锚点共识否决；只有单一反对源或稀疏重复短句时仍保留精确结果，Spotify 官方时间轴始终最高优先
- 队列边界若下一首时长先以“旧标题 + 接近零进度”出现，而新标题暂时报 0，可在 2.2 秒严格窗口内接管该时长，提前触发歌词请求且不会污染普通同曲校正
- 启动时会短暂隔离 Windows 媒体会话可能残留的旧进度锚点；检测到 Spotify 的权威修正后提前放行，最迟 3.2 秒进入稳定时钟
- 同标题下突然出现的大幅时长变化和接近零的进度会先进入归属确认，不会在队列边界把下一首时长套到上一首或反向污染歌词缓存
- 私有 Mix 曲线暂时不可读时保持 Spotify 原生时间，不凭时长差推断整首变速；只有有效的显式速度曲线参与时间映射，淡出端点不用于整首拉伸
- 日中交错歌词会拆为原文与翻译轨；统计忽略装饰性 `♪`，并通过跨源锚点识别开头、中段和结尾缺失，缓存修订号会淘汰旧错误结果
- 短句重复的歌曲尾声也参与跨源完整性证明；类似连续副歌不再因为字数少而被误判为装饰行并吞掉
- 候选录音时长必须通过绝对差或 0.82–1.18× 的版本可行性门槛；同名现场版、加长版和错误歌曲不会被强行拉伸到当前 Spotify 时间轴
- 有可用 Spotify 授权时优先把 Spotify 自带同步歌词作为时间参考；没有 Spotify 歌词或授权时自动回退 LRCLIB、网易云和酷狗
- 空白时间戳不会再让透明歌词窗在歌曲尾部消失；旧缓存会在显示时同步清理
- 暂时没有同步歌词时可在主歌词区直接重新匹配；瞬时网络失败不会永久缓存为空结果
- 歌词源开头带时间戳的“歌手 - 歌名”等制作元数据会在严格匹配后移除，不会抢占第一句歌词
- 悬浮窗和控制条使用轻量内存状态，不再各自反序列化整座歌词资料库；缩放时的重复形状 IPC 也已合并
- 播放进度更新不再重复序列化或写入整座歌词资料库；设置和歌词真正改变时仍立即持久化
- 解锁悬浮窗会自动退出歌词文字穿透，保证直接拖动立即可用，透明空白像素仍然穿透
- 歌词本体和悬停控制条都使用主进程逻辑坐标拖动；混合 DPI 显示器之间移动不会再发生尺寸累积或控制窗抢位
- 控制条显隐由悬停/拖动事件驱动，不常驻轮询全局鼠标；主客户端时钟以 160 ms 刷新，桌面歌词保持独立 80 ms 精细刷新
- 长日文/中文歌词使用平衡换行，避免最后一行只剩两三个孤字；字号、等宽字面和同步时钟不受影响
- 主界面在第一句歌词尚未开始时也把同步位置明确定义为列表顶部；手动浏览后“回到当前歌词”不再因活动行索引为 -1 或后台 `requestAnimationFrame` 暂停而失效
- 歌词请求以曲目身份、时长桶、Provider 上下文和重试代次共同校验；上一首的慢响应、旧罗马音 Worker 或旧重试不能覆盖当前歌曲
- 缓存原文与在线原文会先显示，日文罗马音改为后台增量补全；短暂断网只更新当前视图，不再覆盖已保存歌词或用户编辑
- SMTC 暂时报 0 时长会保留同曲缓存，并在 4 秒后使用不截断时钟的有界降级请求，避免歌词一直空白或进度冻结在 0
- 主进程对所有播放入口共享同一切歌事务；下一首/上一首在确认新曲稳定 250 ms 或 6 秒超时前只接受一次，切歌期间暂停、跳转和其他窗口的重复命令不会与 Spotify 抢控制权
- 本地媒体桥接在切歌时短暂空快照中保留上一条有效身份，失败则按事务回滚，不会把空状态误当成新曲或连续触发多个后端

本地候选产物为 `release/Syllable-0.4.23-Portable.zip` 和 `release/Syllable-0.4.23-Setup.exe`，未上传为GitHub Release。便携包解压后运行 `Syllable.exe`。当前构建没有商业代码签名证书；请先核对来源和文件哈希，不要把版本号或测试通过当作安全签名。源码开发需要 Node.js 20 或更高版本：

```bash
npm install
```


## 使用

1. 打开 Spotify Windows 桌面端并播放任意歌曲。
2. 启动 Syllable；顶部出现“本机 Spotify 实时同步”即连接成功。
3. 在右侧同时启用需要的语言，点击“显示桌面歌词”。
4. 在“悬浮窗外观”中调整大小、背景、透明度、圆角和文字效果；未锁定时拖动歌词或窗体上沿附着式控制栏的手柄，窗口四边可原生缩放。
5. 歌词不匹配时，点击歌曲标题右侧的铅笔进入搜索与校时工作台。
6. 主界面歌词区可直接上下滚动；手动浏览后点击右下角“回到当前歌词”恢复自动跟随。

快捷键：

- `Ctrl + Alt + S`：打开并聚焦 Syllable 主客户端
- `Ctrl + Alt + L`：显示或隐藏悬浮歌词
- `Ctrl + Alt + M`：开启或关闭整窗鼠标穿透

## 可选：Spotify Web API

非 Windows 环境或需要 Spotify Connect 时可以使用 PKCE：

1. 在 [Spotify Developer Dashboard](https://developer.spotify.com/dashboard) 创建应用。
2. 添加 Redirect URI：`http://127.0.0.1:43821/callback`。
3. 将 Client ID 填入 Syllable 设置栏并连接。

桌面应用不保存 Client Secret；刷新令牌优先通过 Electron 系统安全存储加密。

## 多语言文件

歌词数据独立于 Spotify。除在线自动补全外，也可一次导入多个 LRC：

```text
song.ja.lrc       日本语原文
song.romaji.lrc   罗马音
song.zh.lrc       中文翻译
song.en.lrc       英文翻译
```

各语言时间戳不必完全相同，渲染器会按最近时间行对齐。导入和校对内容按歌曲 ID 保存，不会被远程结果覆盖。

## 架构

```text
Windows Spotify SMTC ──> Worker 隔离层 ─┐
Spotify Mix recipe ─────> cue 诊断 / 有效变速积分 ├──> PlaybackSnapshot ──> 歌词时钟
Spotify Web API ────────> PKCE / 采样器 ┘                              │
                                                                      │
LRCLIB ────────────────┐               │                              ├──> 主窗口
网易云翻译 / 罗马音 ───┼──> Provider 管线 ──> 多语言时间轴 / 逐曲缓存 ─┤
酷狗同步歌词 ──────────┤                                              │
本地 LRC / 编辑器 ─────┘                                              └──> 悬浮窗
```

关键模块：

- `electron/local-spotify.ts`：Windows 媒体会话 Worker 与可靠控制
- `electron/spotify-transition.ts`：Spotify 自定义 Mix 的 cue、淡化、重叠和速度曲线解析（cue 不参与传输偏移）
- `electron/spotify.ts`：Spotify PKCE、令牌刷新和 Web API 采样
- `electron/lyrics-provider.ts`：多歌词源、超时、评分和降级策略
- `electron/romanizer.ts`：Kuromoji + Kuroshiro 日文罗马音
- `src/lib/clock.ts`：单调传输时钟与 Spotify Mix → 原曲时间的分段积分
- `src/lib/lyrics.ts`：LRC 解析、检索、导出和多轨对齐

歌词可能受版权保护；在线 Provider 可能受地区、网络和服务条款影响。本地导入与编辑始终可用。
